# Lifecycle failures in dictation cleanup and CLI ASR close

**Date:** 2026-08-05 15:33
**Files:** `src/nadikt/application/services/dictation_pipeline.py`, `src/nadikt/presentation/cli/windows_dictation_slice.py`, `tests/unit/test_dictation_pipeline.py`, `tests/unit/test_windows_dictation_slice_cli.py`
**Severity:** high

## Problem

Two review blockers were found in the Windows dictation slice lifecycle:

- successful pipeline work could still raise `AudioCaptureError: temp_cleanup_failed` from audio cleanup, hiding the already computed safe outcome;
- the CLI could leave a loaded ASR engine open when an exception happened after `build_windows_dictation_slice()` returned.

## Root Cause

Both bugs came from treating cleanup as part of the main control path instead of terminal best-effort resource settlement.

- `DictationPipelineService.run_once()` returned from the main `try`, but `finally` called `audio_capture.cleanup()` without catching adapter failures. Python lets `finally` exceptions override pending returns.
- `windows_dictation_slice.main()` closed the ASR engine on happy path and target-capture failure only. Exceptions from pipeline execution or clipboard settlement skipped those explicit close calls.

## Solution

Added regression tests first, confirmed both failures, then applied minimal lifecycle fixes:

- wrap audio cleanup in `try/except` inside pipeline `finally`, log `[FIX] dictation_pipeline.audio_cleanup.failed`, and preserve the primary pipeline outcome;
- wrap post-composition CLI execution in `try/finally` and always call `_close_loaded_engine()` when components exist;
- redact ASR close failures through `[FIX] windows_dictation_slice.asr_close.failed` without leaking SDK or local path payload.

## Prevention

- During review, check every `finally` block that can raise while a return is pending.
- Resource cleanup for audio, clipboard and ASR engines should be best-effort unless the cleanup failure is itself the requested user-facing outcome.
- CLI composition that loads external resources must centralize close/release in one `finally`, not duplicate close calls across branches.
- Add regression tests for cleanup failure and resource close on post-load exceptions whenever introducing a new lifecycle boundary.
