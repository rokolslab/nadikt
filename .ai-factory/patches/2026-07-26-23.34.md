# Safety defects в Windows insertion spike

**Date:** 2026-07-26 23:34
**Files:** `experiments/windows_insertion/insertion_spike/contracts.py`, `service.py`, `windows_clipboard.py`, `windows_injector.py`, `windows_target.py`, `cli.py`, controlled fixtures и tests
**Severity:** critical

## Problem

Независимая verification обнаружила, что fake API tests пропустили несколько
Win32 и orchestration defects:

- `OpenClipboard(NULL)` использовался перед `EmptyClipboard`/`SetClipboardData`;
- target проверялся до clipboard/modifier work, а не перед input dispatch;
- clipboard racer мог перезаписать произвольный пользовательский clipboard;
- portable token физически содержал Win32 identity;
- partial composition и synthetic-key cleanup имели неполный cleanup.

## Root Cause

Contracts моделировали успешные adapter outcomes, но не проверяли обязательные
предусловия системных API и точный порядок side effects. Термин "final
revalidation" был проверен только по числу вызовов, без события modifier wait
между assessment и `SendInput`. Fake clipboard facade также не моделировал
Win32 ownership rule, связывающее `OpenClipboard`, `EmptyClipboard` и
`SetClipboardData`.

## Solution

- Добавлен private message-only owner HWND и deterministic close lifecycle.
- Modifier preflight перенесён до финальной target assessment; после неё
  остаются только non-blocking modifier check и dispatch.
- Platform identity хранится во внутреннем store Windows adapter, token несёт
  только случайный opaque key.
- Clipboard racer требует confirmation и точного synthetic CLI precondition.
- Win32 style errors трактуются fail-closed, partial key cleanup журналируется.
- Controlled self-check теперь возвращает non-zero при несовпадении результата.
- Добавлены regression tests порядка orchestration, owner HWND, racer guards,
  composition cleanup и error paths.

## Prevention

- Для Win32 adapters проверять не только return values, но и ownership/lifetime
  contracts из API documentation.
- В race-sensitive tests фиксировать порядок событий, а не только конечный
  outcome или число вызовов.
- Любой fixture, меняющий global OS state, должен требовать confirmation и
  проверяемое synthetic precondition до mutation.
- Portable opaque token не должен содержать platform object или raw identity.
- Acceptance self-check обязан завершаться non-zero при любом failed case.
- После реализации safety spike запускать fresh-context review, потому что
  injected fakes могут скрывать системные предусловия.
