# Atomic lifecycle для clipboard и synthetic input

**Date:** 2026-07-27 00:02
**Files:** `experiments/windows_insertion/insertion_spike/service.py`, `windows_clipboard.py`, `windows_injector.py`, `cli.py`, controlled fixture и tests
**Severity:** critical

## Problem

Code review после первоначальной verification обнаружил, что успешный
`SendInput` подтверждает только queueing, поэтому timer-based restoration мог
подставить исходный clipboard в delayed target. Дополнительно restore/discard
могли конкурировать с active delivery, interruptions обходили recovery, partial
multi-format writes не имели безопасного retry, а неизвестный input outcome мог
оставить synthetic key в состоянии down.

## Root Cause

Clipboard mutation, input dispatch и restoration рассматривались как отдельные
операции, хотя безопасность требует единого transaction lifecycle. Tests
проверяли конечные outcomes, но не interleaving concurrent operations,
ownership transfer handles и interrupts между системным вызовом и обновлением
локального state.

## Solution

- `deliver`, explicit restore и discard сериализованы одним transaction lock.
- После queued paste timer restoration запрещена; operator выбирает `RESTORE`
  или явный destructive `DISCARD_ORIGINAL`.
- Pending snapshot блокирует новые requests, а adapter discard удаляет свой
  sensitive state.
- Multi-format handles preallocated до `EmptyClipboard`; ordinary partial
  failures получают bounded retry и retryable sequence marker.
- `BaseException` на adapter boundary преобразуется в controlled recovery, но
  low-level ownership transfer не ретраит interruption с неизвестным owner.
- Injector poison устанавливается до `SendInput` и снимается только после
  полного dispatch либо подтверждённого per-key cleanup.
- Controlled fixture проверяет foreground/focus и guard-ит каждый реальный
  input call.

## Prevention

- Проектировать global OS mutation как одну state machine с единым lock и
  явными terminal states.
- Не считать queued input consumed input и не восстанавливать clipboard по
  fixed delay.
- Добавлять deterministic concurrency tests для check-before-lock races.
- До destructive clipboard mutation preallocate все owned resources.
- При неизвестном результате input API считать injector poisoned до
  подтверждённого cleanup.
- Review должен проверять interrupts в каждой точке ownership transfer, а не
  только ordinary exceptions.
