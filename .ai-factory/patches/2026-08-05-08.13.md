# GigaAM warm-up failed because controlled ffmpeg was not on PATH

**Date:** 2026-08-05 08:13
**Files:** `src/nadikt/infrastructure/asr/gigaam.py`, `tests/contract/test_gigaam_probe.py`, `benchmarks/asr/worker_supervisor.py`, `tests/contract/test_worker_supervisor.py`, `.ai-factory/plans/prepare-gigaam-offline-monitor-task11.md`
**Severity:** high

## Problem

The opt-in real local ASR load regression check failed for `gigaam-multilingual-220m` with worker status `fail` and phase `warm_up_failed`. `load`, `readiness`, and `close` were successful, but GigaAM could not transcribe the controlled warm-up sample.

## Root Cause

The GigaAM SDK invokes `ffmpeg` by executable name during `transcribe`. The controlled WSL2 ffmpeg binary existed outside Git under the controlled root, but the spawned worker did not include that directory in `PATH`. The adapter treated the resulting SDK exception as a generic `transcribe_failed`, which became `warm_up_failed` in the lifecycle check.

## Solution

`GigaAMAsrEngine` now resolves a local ffmpeg executable from either `inference_defaults.ffmpeg_path`/`ffmpeg_executable` or the controlled-root tool layout next to the model package. During SDK `transcribe`, it temporarily prepends only the ffmpeg directory to `PATH` and restores the original `PATH` afterward. The fix logs only safe outcome events with `[FIX]` and does not log private paths.

The supervisor was also adjusted so benign SDK stderr is privacy-audited and not published, but no longer automatically fails a worker. Stderr containing private paths, traceback markers, canaries, credentials, or forbidden payload markers still fails closed with `privacy_error`.

## Prevention

- For local ASR SDKs that shell out to tools, model package or controlled environment checks must verify executable discovery, not only Python imports and model files.
- Do not rely on ambient `PATH` in spawned benchmark workers; pass or discover controlled local tools explicitly and restore environment changes after the SDK call.
- Keep stderr fail-closed through privacy audit, but do not classify all benign SDK warning output as a lifecycle failure.
- Regression coverage should include a fake GigaAM model that observes temporary `PATH` injection and confirms restoration after `transcribe`.
