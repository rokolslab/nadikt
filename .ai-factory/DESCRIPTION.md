# Nadikt

## Обзор

Nadikt - автономная фоновая утилита голосового ввода для Windows 10/11 x64. Она локально преобразует преимущественно русскую речь, включая отдельные английские термины, в редактируемый текст и безопасно вставляет результат в активное приложение. Аудио, распознанный текст и пользовательский словарь не передаются во внешние сервисы.

Первым законченным продуктом является Windows MVP. Общее ядро разрабатывается независимо от ОС, чтобы после MVP добавить Ubuntu-версию без повторной реализации ASR, VAD, словаря и нормализации.

## Основные функции

- Запуск, остановка и отмена диктовки глобальной горячей клавишей.
- Режимы `toggle` и `push-to-talk`.
- Локальный захват аудио, предварительный буфер, VAD и сегментация длинных записей.
- Сменные локальные ASR-движки через единый внутренний интерфейс.
- Режимы распознавания «Русский» и «Русский + English».
- Пользовательский словарь, правила замен, голосовые команды форматирования и детерминированная нормализация.
- Безопасная вставка в целевое окно с резервным сохранением результата и восстановлением буфера обмена.
- Плавающий индикатор без перехвата фокуса, системный трей, настройки и самодиагностика.
- Автономные версионируемые модельные пакеты с лицензиями и контрольными суммами.

## Технологический стек

- **Язык программирования:** Python.
- **Desktop UI:** PySide6 (Qt 6).
- **Локальное хранилище:** SQLite.
- **Доступ к данным:** стандартный модуль `sqlite3`, без ORM.
- **ASR:** адаптеры для GigaAM и faster-whisper; окончательные модели выбираются по результатам сравнительного прототипа.
- **Целевые ОС:** Windows 10/11 x64 для MVP; Ubuntu после Windows MVP.
- **Среда разработки:** WSL2 Ubuntu на Windows 11 Pro; текущая машина разработки - mini PC с Intel Core i3 12-го поколения и 16 ГБ ОЗУ. Windows host и Windows CI используются для системной интеграции, сборки и приёмочных проверок.

Точные библиотеки аудиозахвата, VAD, глобальных горячих клавиш, безопасной вставки и упаковки ещё не утверждены. Их следует выбирать по воспроизводимым прототипам на целевом ПК, а не фиксировать до измерений.

## Архитектурные положения

- Общее ядро не зависит от Windows API, Qt и конкретного ASR-движка.
- Платформенные функции скрыты за контрактом адаптера; MVP реализует `WindowsAdapter`, будущая версия - `LinuxAdapter`.
- Захват аудио, VAD/сегментация, ASR, сборка текста, нормализация, словарь, вставка и UI разделены контрактами.
- В памяти одновременно находится только одна основная ASR-модель; смена движка во время записи запрещена.
- Ошибка одного сеанса не завершает фоновый процесс и не уничтожает уже полученный результат.
- Состояние диктовки управляется явно; параллельные сеансы и двойная вставка запрещены.
- Настройки и локальные данные поддерживают миграции и безопасную атомарную запись.
- Проектная документация в `docs/` является каноническим источником продуктовых требований; файлы `.ai-factory/` служат контекстом разработки.

## Архитектура

Подробные правила слоёв, зависимостей и целевой структуры находятся в `.ai-factory/ARCHITECTURE.md`.

**Шаблон:** Explicit Architecture (Technical Layer).

**Стратегия кодовой базы:** `HYBRID` - самостоятельная Python/PySide6 реализация с выборочным использованием проверенных архитектурных решений и только отдельно одобренных permissive-компонентов. Решение и условия пересмотра зафиксированы в `docs/architecture/ADR-001-codebase-strategy.md`.

## Нефункциональные требования

- **Автономность:** основные функции, установка модельных пакетов и распознавание работают без интернета.
- **Конфиденциальность:** аудио и распознанный текст не попадают в журналы, дампы, отчёты или телеметрию; автоматическая телеметрия отсутствует.
- **Производительность:** приложение должно работать на CPU-only Intel Core i3 class, 16 ГБ ОЗУ и без дискретной видеокарты; текущая development/benchmark машина - i3 12-го поколения. UI остаётся отзывчивым во время загрузки и распознавания.
- **Надёжность:** пользователь не теряет готовый или частичный результат при ошибке вставки либо отдельного сегмента.
- **Безопасность:** текст не вставляется в другое окно или защищённое поле; голосовые команды не запускают программы и системные действия.
- **Совместимость:** обязательная проверка включает Блокнот, Microsoft Word, браузерные поля и 1С.
- **Поставка:** конечному пользователю не нужны Python, Node.js, Rust, среда разработки или командная строка.

## Текущие артефакты реализации

- Начальный SDK-neutral ASR contract находится в `src/nadikt/domain/ports/asr.py`.
- Начальный pure-domain text normalization/dictionary spike находится в `src/nadikt/domain/text/`; он предоставляет generic coding-term rule mechanics без ASR SDK, SQLite, UI и benchmark-private данных.
- Локальный ASR benchmark protocol, manifests, dry-run, offline package probe и results template находятся в `docs/research/local_asr_performance_benchmark_plan.md`, `docs/research/local_asr_offline_package_prototype.md`, `benchmarks/asr/`, `model_packs/` и `docs/research/local_asr_performance_benchmark_results.md`.
- Benchmark dry run и local package probe не скачивают модели, не выполняют сетевые вызовы и проверяют manifests/package integrity/safe failure outcomes; real model loads выполняются только при наличии локальных packages вне Git.

## Контрольные решения прототипа

- Выбрать CTC или RNN-T вариант GigaAM-v3-e2e для русского режима.
- Сравнить GigaAM Multilingual 220M и Whisper small INT8 через faster-whisper для смешанной речи.
- Проверить целесообразность T-one как облегчённого потокового кандидата.
- Зафиксировать VAD, размер предварительного буфера, RTF, загрузку CPU, потребление ОЗУ и задержки на эталонном ПК.
- Утвердить формат модельных пакетов, механизм упаковки приложения и ограничения вставки в поддерживаемые приложения.
