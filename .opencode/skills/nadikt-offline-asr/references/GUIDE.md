# Справочник по автономному ASR Nadikt

## GigaAM

Официальный репозиторий указывает Python 3.10+ и установленный в системе `ffmpeg` как требования пакета. Семейство включает CTC и RNN-T варианты; `v3_e2e_ctc` и `v3_e2e_rnnt` поддерживают пунктуацию и нормализацию. Многоязычная линия предоставляет charwise CTC-модели 220M и 600M для 70+ языков, при этом качество английского описано как умеренное.

Критичное ограничение: `.transcribe` предназначен для аудио продолжительностью не более 25 секунд. Официальный `.transcribe_longform` требует дополнительного набора зависимостей, Hugging Face token и принятия условий доступа к `pyannote/segmentation-3.0`. Это не соответствует автономному runtime Nadikt. Следовательно, Nadikt должен сегментировать длинный поток собственным общим VAD-слоем и передавать движку допустимые сегменты.

Официальный пример загружает модель через `gigaam.load_model(model_name)`, но изученный README не документирует контракт автономной загрузки произвольного локального модельного пакета. Нельзя придумывать этот API. До реализации адаптера нужно проверить исходный код и создать offline-прототип с заранее подготовленными файлами и заблокированной сетью.

## faster-whisper

faster-whisper запускает Whisper через CTranslate2. Официальный README заявляет Python 3.9+, декодирование через PyAV без системной установки FFmpeg и поддержку CPU INT8.

Базовая конфигурация целевого CPU:

```python
from faster_whisper import WhisperModel

model = WhisperModel(local_model_path, device="cpu", compute_type="int8")
segments, info = model.transcribe(audio_path, beam_size=5)
text = "".join(segment.text for segment in segments)
```

`segments` является генератором: до его итерации фактическая транскрипция не начинается. Время benchmark, которое не потребляет генератор полностью, недействительно.

Передача имени вроде `small` может инициировать загрузку модели из Hugging Face Hub. В поставке Nadikt конструктор должен получать только каталог локальной CTranslate2-модели из проверенного модельного пакета.

Встроенный Silero VAD включается через `vad_filter=True`; в batched transcription он включён по умолчанию. Nadikt требуется общий и сопоставимый segmentation pipeline, поэтому использование встроенного VAD должно быть явным и одинаково учтённым в эксперименте. Нельзя сравнивать движки, если один получает очищенные сегменты, а другой необработанное аудио.

## Модельный пакет

Пакет должен содержать:

- точное имя и ревизию модели;
- версию backend;
- конфигурацию inference;
- файлы весов и tokenizer/config;
- лицензию модели и перечень компонентов;
- checksum каждого критичного файла или подписанный манифест;
- диапазон совместимых версий Nadikt;
- заявленные языки и возможности;
- формат/precision, например CTranslate2 INT8.

Установщик проверяет пакет до регистрации. Runtime не исправляет неполный пакет загрузкой из сети.

## Контракт и границы

Контракт Nadikt нормализует различия backend и возвращает собственный тип результата сегмента. Он не должен обещать функции, которых нет у всех реализаций. Дополнительные возможности, например word timestamps, объявляются через capabilities и используются только после проверки.

Сегментация отвечает за:

- предварительный буфер;
- обнаружение речи;
- допустимую длину сегмента;
- overlap или другой подтверждённый способ защиты границ;
- монотонную нумерацию;
- ограниченное потребление памяти.

Сборщик результата отвечает за порядок, дедупликацию подтверждённых перекрытий, обозначение частичного результата и передачу текста в детерминированную постобработку.

## Честное сравнение

Сравнивай кандидаты при максимально одинаковых условиях:

- одинаковые аудиофайлы и segmentation manifest;
- одинаковая политика пунктуации и постобработки;
- зафиксированные beam size, CPU threads, precision и batch size;
- отдельные cold/warm измерения;
- одинаковая методика WER/CER;
- одинаковый способ измерения пикового RSS и CPU;
- несколько повторов после прогрева;
- отсутствие фоновой загрузки либо её фиксированный профиль.

Опубликованные результаты faster-whisper для Intel Core i7-12700K не доказывают производительность на эталонном Intel Core i3 10-го поколения. Они служат только исходной гипотезой для собственного измерения.
