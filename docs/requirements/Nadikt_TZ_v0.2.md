# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## На разработку автономной утилиты голосового ввода «Надикт»

**Наименование продукта:** «Надикт»  
**Латинское написание:** `Nadikt`  
**Версия документа:** 0.2  
**Статус:** обновлённая согласованная редакция MVP  
**Основные целевые ОС:** Windows 10 и Windows 11 x64  
**Перспективная ОС:** Ubuntu  
**Дата:** 26 июля 2026 г.

> **Назначение:** быстрое автономное преобразование речи с микрофона в редактируемый текст и его вставка в активное приложение без передачи аудио или текста во внешние сервисы.

## 1. Общие положения

### 1.1. Цель разработки

Разработать удобную фоновую утилиту для диктовки резолюций и другого текста в любое поддерживаемое приложение Windows.

Программа должна:

- запускать и останавливать запись глобальной горячей клавишей;
- локально распознавать преимущественно русскую речь;
- распознавать русскую речь с отдельными английскими терминами;
- обрабатывать голосовые команды форматирования;
- автоматически вставлять результат в активное текстовое поле;
- сохранять результат при невозможности автоматической вставки;
- работать на целевом ПК без дискретной видеокарты;
- после установки выполнять основные функции без доступа к интернету.

### 1.2. Границы MVP

В MVP входят:

- один пользователь;
- один выбранный активный микрофон;
- Windows 10/11 x64;
- русская речь;
- русская речь с отдельными английскими словами, названиями, аббревиатурами и техническими терминами;
- ручной выбор режима распознавания;
- полностью локальные ASR-движки и модельные пакеты;
- пользовательский словарь и правила замен;
- голосовые команды форматирования;
- вставка текста в активное приложение.

В MVP не входят:

- извлечение исполнителей, сроков, поручений и другой смысловой структуры резолюции;
- перевод речи между языками;
- полноценная диктовка документов на произвольных иностранных языках;
- облачная обработка;
- облачная синхронизация;
- постоянное хранение истории диктовок;
- распознавание нескольких говорящих;
- разделение говорящих по ролям;
- редактор документов внутри утилиты;
- законченная версия для Ubuntu.

Архитектура должна позволять последующую разработку Ubuntu-версии без повторной реализации общего ядра.

### 1.3. Термины

| Термин | Определение |
|---|---|
| Активное приложение | Приложение, в текстовое поле которого пользователь устанавливает курсор перед началом диктовки |
| Целевое окно | Окно и, если это возможно определить, текстовое поле, запомненные при начале диктовки |
| Глобальная горячая клавиша | Комбинация клавиш, обрабатываемая утилитой независимо от активного приложения |
| Голосовая команда | Заранее определённая произносимая фраза, преобразуемая в знак препинания или управляющий символ |
| ASR | Автоматическое распознавание речи |
| ASR-движок | Программный компонент, выполняющий запуск ASR-модели и преобразование аудио в текст |
| ASR-модель | Набор обученных весов и связанных файлов, используемый ASR-движком |
| Модельный пакет | Автономный комплект модели, конфигурации, лицензии, метаданных и контрольной суммы |
| VAD | Локальный механизм определения речевой активности и границ речевых сегментов |
| RTF | Отношение времени распознавания к длительности обрабатываемого аудио |
| Смешанная речь | Русская речь, содержащая отдельные английские слова, термины, названия или обозначения |

## 2. Пользовательские сценарии

### 2.1. Основной режим «нажал/нажал»

1. Пользователь устанавливает курсор в нужное текстовое поле.
2. Нажимает глобальную горячую клавишу. По умолчанию используется `Ctrl+Alt+Space`.
3. Утилита запоминает целевое окно, начинает запись, показывает плавающее окно и при включённой настройке воспроизводит сигнал.
4. Пользователь диктует текст произвольной длины.
5. Повторное нажатие горячей клавиши завершает запись.
6. Утилита завершает обработку оставшихся сегментов и формирует итоговый текст.
7. Выполняются включённые команды форматирования, нормализация и пользовательские замены.
8. Перед вставкой утилита проверяет целевое окно.
9. Текст вставляется в текстовое поле и может быть сразу отредактирован пользователем.

### 2.2. Режим push-to-talk

Если в настройках выбран push-to-talk:

1. нажатие и удержание назначенной клавиши запускает запись;
2. отпускание клавиши завершает запись;
3. короткое случайное нажатие без речи не создаёт пустую вставку;
4. дальнейшая обработка выполняется как в основном сценарии.

### 2.3. Отмена

Нажатие `Esc` во время записи или распознавания отменяет текущую диктовку:

- текст не вставляется;
- временные аудиоданные удаляются;
- прежнее содержимое буфера обмена не изменяется;
- утилита возвращается в состояние готовности.

### 2.4. Неудачная вставка

Если автоматическая вставка невозможна:

- распознанный текст помещается в буфер обмена;
- результат сохраняется в оперативной памяти как последний;
- пользователь получает понятное уведомление;
- фоновый процесс продолжает работу.

## 3. Функциональные требования

### 3.1. Фоновая работа и системный трей

- После запуска утилита работает в фоновом режиме.
- В области уведомлений Windows отображается значок программы.
- Меню значка содержит:
  - начало или остановку записи;
  - отмену активной диктовки;
  - копирование последнего результата;
  - выбор режима распознавания;
  - открытие настроек;
  - запуск самодиагностики;
  - сведения о программе;
  - выход.
- Закрытие окна настроек не завершает утилиту.
- Автозапуск вместе с Windows включается и отключается в настройках.
- Одновременная работа нескольких конфликтующих экземпляров программы не допускается.
- Повторный запуск активирует существующий экземпляр или сообщает, что программа уже работает.

### 3.2. Глобальная горячая клавиша

- Комбинация по умолчанию — `Ctrl+Alt+Space`.
- Пользователь может назначить другую комбинацию.
- Программа проверяет корректность комбинации и сообщает:
  - о невозможности регистрации;
  - о конфликте;
  - об использовании запрещённой или неподдерживаемой комбинации.
- Поддерживаются режимы:
  - «нажал/нажал»;
  - push-to-talk.
- `Esc` отменяет текущую диктовку без вставки.
- В настройках предусматривается временное отключение глобальных горячих клавиш.
- Во время активной записи запрещается запуск второго сеанса.

### 3.3. Плавающее окно

- Во время записи поверх остальных окон отображается компактное полупрозрачное окно.
- Окно не перехватывает клавиатурный фокус.
- Окно не изменяет активное поле ввода.
- Во время записи отображаются:
  - статус;
  - длительность;
  - анимированная волна, синусоида или эквалайзер;
  - визуальная реакция на громкость микрофона.
- После остановки отображается состояние «Распознавание…».
- Анимация распознавания отличается от анимации записи.
- После успешной вставки окно автоматически скрывается.
- Отмена и ошибки показываются понятным ненавязчивым состоянием.
- Пользователь может настроить положение и прозрачность окна.
- Положение корректно обрабатывается при нескольких мониторах и различном масштабировании Windows.
- Если ранее выбранный монитор недоступен, окно возвращается на основной монитор.

### 3.4. Запись звука

- Запись выполняется с выбранного микрофона.
- По умолчанию используется системное устройство ввода.
- Настройки содержат список доступных устройств.
- Предусматриваются проверка микрофона и отображение уровня сигнала.
- До начала пользовательской речи используется короткий кольцевой аудиобуфер либо эквивалентный механизм, предотвращающий потерю первого слога или слова.
- Рекомендуемая продолжительность предварительного буфера — не менее 300 мс; точное значение уточняется испытаниями.
- Программное ограничение максимальной длительности диктовки не устанавливается.
- Аудиопоток обрабатывается фрагментами.
- Потребление памяти не должно расти пропорционально полной длительности записи.
- Длительная пауза сама по себе не завершает диктовку в режиме «нажал/нажал».
- Тишина может не передаваться в ASR после обработки VAD.
- При отсутствии разрешения, недоступности или отключении микрофона пользователь получает понятное уведомление.
- Отключение микрофона во время записи не должно приводить к аварийному завершению программы.
- Аудио по возможности обрабатывается в оперативной памяти.
- Если используются временные файлы, они удаляются после:
  - успешного распознавания;
  - отмены;
  - обработанной ошибки;
  - восстановления после аварийного завершения.

### 3.5. Режимы распознавания

В MVP предусматриваются:

#### 3.5.1. «Русский»

- Режим предназначен для преимущественно русской речи.
- Основной кандидат — GigaAM-v3-e2e.
- Конкретный вариант CTC или RNN-T выбирается после сравнительного теста.

#### 3.5.2. «Русский + English»

- Режим предназначен для русской речи с отдельными английскими словами, названиями, аббревиатурами и техническими терминами.
- Английские термины по возможности сохраняются латиницей.
- Модель выбирается по результатам сравнения:
  - GigaAM Multilingual 220M;
  - Whisper small INT8 через faster-whisper;
  - иного локального кандидата, удовлетворяющего настоящему ТЗ.

#### 3.5.3. Общие правила

- Пользователь вручную выбирает режим.
- Выбор сохраняется между запусками.
- Автоматическое переключение модели внутри фразы в MVP не используется.
- Одновременное распознавание одной записи двумя тяжёлыми моделями не используется.
- Во время записи смена модели запрещена.
- В памяти одновременно находится только одна основная ASR-модель.

### 3.6. Длительная диктовка

- Стандартное ограничение конкретной ASR-модели на длину входного фрагмента не должно ограничивать пользовательский сеанс.
- Аудио локально делится VAD или эквивалентным механизмом на допустимые для выбранной модели сегменты.
- Длительность сегментов выбирается с учётом ограничений движка.
- Сегменты обрабатываются последовательно и в правильном порядке.
- Допускается распознавание сегментов во время записи.
- Вставка итогового текста выполняется после завершения диктовки.
- На границах сегментов не допускаются:
  - потеря слов;
  - повтор слов;
  - перестановка фрагментов;
  - необоснованное объединение или разделение слов.
- Уже распознанные сегменты не должны теряться при обработанной ошибке последующего сегмента.
- При частичной ошибке пользователь получает либо полный результат, либо явно обозначенный частичный результат.

### 3.7. Пользовательский словарь и нормализация

Пользовательский словарь должен поддерживать:

- русские слова;
- английские слова;
- фамилии и имена;
- названия продуктов и организаций;
- аббревиатуры;
- буквенно-цифровые обозначения;
- пары «ошибочный вариант → правильный вариант».

Требования:

- словарь применяется независимо от ASR-движка;
- записи можно добавлять, изменять, удалять и искать;
- изменение словаря не требует перезапуска программы;
- словарь хранится локально;
- словарь не синхронизируется с внешними сервисами;
- правила не должны выполнять произвольные программы или системные команды;
- при конфликте правил используется предсказуемый документированный порядок.

Нормализация должна обрабатывать:

- лишние пробелы;
- пробелы перед знаками препинания;
- пробелы после знаков препинания;
- регистр начала предложения;
- переносы строк и абзацы;
- числа, даты и обозначения в объёме, подтверждённом испытаниями.

Постобработка не должна изменять смысл продиктованного текста.

### 3.8. Голосовые команды форматирования

В настройках предусматривается флажок «Использовать голосовые команды».

Автоматическая пунктуация ASR-модели не зависит от этого флажка.

| Произнесённая команда | Результат |
|---|---|
| новая строка | Перевод строки |
| новый абзац / абзац | Новый абзац |
| точка | `.` |
| запятая | `,` |
| двоеточие | `:` |
| точка с запятой | `;` |
| вопросительный знак | `?` |
| восклицательный знак | `!` |
| открыть кавычки | Открывающая кавычка |
| закрыть кавычки | Закрывающая кавычка |
| дефис | `-` |
| тире | `—` |

Дополнительные требования:

- команды распознаются без учёта регистра;
- перечень команд хранится централизованно;
- расширение перечня не требует изменения ASR-модуля;
- после подстановки нормализуются пробелы и регистр;
- при выключенном флажке команды остаются обычными словами;
- должен быть документирован способ продиктовать слово, совпадающее с командой, буквально;
- команды форматирования не запускают программы и не выполняют системные действия.

### 3.9. Вставка текста

- При начале диктовки программа запоминает целевое окно.
- Перед вставкой программа проверяет, что текст не будет направлен в другое окно.
- Если фокус изменился, автоматическая вставка не выполняется без подтверждённого безопасного способа.
- Успешно распознанный текст перед попыткой вставки всегда становится доступен для восстановления.
- Поддерживаются:
  - вставка через буфер обмена;
  - резервная имитация ввода;
  - режим «только в буфер обмена».
- Перед использованием буфера программа сохраняет его прежнее содержимое.
- После подтверждённой вставки прежнее содержимое восстанавливается.
- Должны корректно обрабатываться как минимум:
  - текст;
  - Unicode-текст;
  - изображения;
  - список файлов — если формат доступен программе через Windows API.
- Если содержимое невозможно безопасно сохранить и восстановить, программа использует безопасный резервный способ либо уведомляет пользователя.
- При невозможности вставки распознанный текст остаётся в буфере обмена.
- Пользователь получает понятное уведомление без потери результата.
- Последний результат хранится только в оперативной памяти:
  - до следующего успешного результата;
  - либо до завершения программы.
- Постоянная история в MVP не создаётся.
- В поля паролей и иные распознанные защищённые поля автоматическая вставка не выполняется.
- Вставка в приложение с повышенными правами не гарантируется при обычном запуске утилиты.
- Ограничение повышенных прав должно быть отражено в руководстве пользователя.

### 3.10. Звуковые сигналы

- Отдельные короткие сигналы обозначают начало и завершение записи.
- Сигналы включаются и отключаются в настройках.
- Сигнал старта не должен попадать в распознаваемое аудио.
- Сигнал завершения воспроизводится после остановки захвата.
- Отключение сигналов не отключает визуальную индикацию.

### 3.11. Настройки

Настройки сохраняются между запусками и включают:

- режим распознавания;
- выбранный ASR-движок в пределах доступных для режима;
- глобальную горячую клавишу;
- режим горячей клавиши;
- временное отключение горячих клавиш;
- устройство ввода;
- голосовые команды;
- звуковые сигналы;
- автозапуск;
- автоматическую вставку или режим «только в буфер»;
- прозрачность и положение плавающего окна;
- пользовательский словарь;
- возврат к значениям по умолчанию.

Настройки записываются атомарно либо эквивалентным безопасным способом.

### 3.12. Самодиагностика

Программа должна выполнять локальную проверку:

- доступности микрофона;
- уровня сигнала;
- регистрации горячей клавиши;
- наличия и целостности модельного пакета;
- загрузки ASR-движка;
- доступного места на диске;
- возможности работы с буфером обмена;
- версии программы и компонентов.

Результат показывается понятным списком без раскрытия аудио или текста пользователя.

### 3.13. Модельные пакеты

Каждый пакет содержит:

- файлы модели;
- конфигурацию;
- точное наименование модели;
- версию или ревизию;
- сведения о разработчике;
- лицензию;
- перечень сторонних компонентов;
- контрольную сумму;
- сведения о совместимости с версиями «Надикта».

Требования:

- установка пакета выполняется без командной строки;
- установка и переключение не требуют интернета;
- отсутствующая модель не загружается автоматически;
- повреждённый пакет не используется;
- пользователь получает понятное сообщение о проблеме;
- должна сохраняться возможность вернуться к последней работоспособной модели.

## 4. Нефункциональные требования

### 4.1. Автономность и конфиденциальность

- После установки основные функции работают без интернета.
- Аудио, промежуточные данные, словарь и распознанный текст не передаются во внешние сервисы.
- Автоматическая телеметрия отсутствует.
- Облачная проверка обновлений отсутствует.
- Программа не создаёт постоянную историю диктовок.
- Аудио по умолчанию не сохраняется.
- Текст и аудио не включаются:
  - в технический журнал;
  - в аварийный отчёт;
  - в диагностический пакет;
  - в телеметрию.
- Программа не должна инициировать сетевые запросы для основного сценария.
- Работа основных функций проверяется при заблокированном исходящем сетевом доступе.

### 4.2. Совместимость

| Параметр | Требование |
|---|---|
| ОС | Windows 10 x64 и Windows 11 x64 |
| Вычисления | CPU; дискретная видеокарта не требуется |
| Среда пользователя | Установленные Python, Rust, Node.js или среда разработки не требуются |
| Права | Обычный запуск без обязательных прав администратора |
| Текст | Полная поддержка Unicode и кириллицы |
| Приложения | Блокнот, Microsoft Word, браузерные поля и 1С входят в обязательную проверку |

### 4.3. Производительность

- Визуальное состояние записи меняется не позднее 1 секунды после горячей клавиши.
- Захват должен начинаться достаточно быстро либо использовать предварительный буфер, чтобы не терять первое слово.
- Интерфейс остаётся отзывчивым при загрузке модели и распознавании.
- Во время распознавания допускается высокая загрузка процессора.
- Не допускается зависание ОС, активного приложения или интерфейса «Надикта».
- Потребление памяти должно оставлять эталонный ПК пригодным для обычной офисной работы.
- Для записи до 60 секунд целевое время завершения остаточной обработки после остановки — не более 30 секунд при нормальной фоновой нагрузке.
- Для длинной диктовки отображается продолжающаяся обработка.
- Уже распознанные сегменты не теряются.

Для каждого поставляемого ASR-движка в протоколе испытаний фиксируются:

- время холодной загрузки;
- время первого распознавания;
- RTF;
- задержка после остановки;
- средняя и максимальная загрузка CPU;
- максимальное потребление ОЗУ.

Точные предельные значения, кроме прямо установленных настоящим ТЗ, уточняются после прототипа и утверждаются до приёмки.

### 4.4. Надёжность

- Ошибка одного сеанса не завершает фоновый процесс.
- После ошибки можно сразу начать новую диктовку.
- Параллельные сеансы запрещены.
- Некорректное повторное нажатие горячей клавиши не создаёт двойную вставку.
- При аварийном завершении временные файлы предыдущего сеанса удаляются при следующем запуске.
- Повреждённые настройки восстанавливаются из безопасного значения или резервной копии.
- Ошибка одного аудиосегмента не должна бесшумно уничтожать остальные результаты.
- При неустранимой ошибке пользователь получает понятное сообщение и способ сохранить доступный текст.

### 4.5. Удобство использования

- Основной сценарий не требует открытия главного окна.
- Пользователь не обязан работать с командной строкой.
- Состояния «Готово», «Запись», «Распознавание», «Отмена» и «Ошибка» визуально различаются.
- Ошибки формулируются понятным языком и содержат рекомендуемое действие.
- Настройки по умолчанию позволяют начать работу после выбора или проверки микрофона.

### 4.6. Переносимость

Основная логика не должна зависеть от Windows API.

Отдельными адаптерами реализуются:

- глобальная горячая клавиша;
- системный трей;
- активное окно;
- вставка текста;
- буфер обмена;
- автозапуск;
- уведомления;
- платформенные разрешения.

Должны быть определены:

- `WindowsAdapter`;
- контракт будущего `LinuxAdapter`.

Версия для Ubuntu не является результатом MVP, но её добавление не должно требовать повторной реализации ASR, VAD, словаря и нормализации.

## 5. Архитектурные требования

### 5.1. Основные компоненты

Архитектура включает:

- общее ядро;
- аудиозахват;
- предварительный буфер;
- VAD;
- сегментацию;
- единый интерфейс ASR;
- адаптер GigaAM;
- адаптер faster-whisper либо иного выбранного движка;
- сборку текста из сегментов;
- нормализацию;
- пользовательский словарь;
- команды форматирования;
- платформенные адаптеры;
- интерфейс;
- конфигурацию;
- диагностику.

### 5.2. Единый интерфейс ASR

Интерфейс должен поддерживать:

- загрузку;
- проверку готовности;
- прогрев;
- распознавание сегмента;
- завершение текущей обработки;
- освобождение ресурсов;
- получение сведений о версии и возможностях.

Добавление нового движка не должно требовать изменения:

- захвата аудио;
- VAD;
- горячих клавиш;
- плавающего окна;
- пользовательского словаря;
- вставки текста.

### 5.3. Управление ресурсами

- Одновременно загружается одна основная ASR-модель.
- При смене движка предыдущая модель выгружается.
- Новый движок проверяется и прогревается.
- Смена во время записи запрещена.
- При ошибке загрузки сохраняется возможность вернуться к работоспособному движку.

### 5.4. Конфигурация

- Конфигурация хранится локально в профиле пользователя.
- Конфигурация не содержит аудио и историю диктовок.
- Формат допускает миграцию при обновлении.
- Повреждение одного параметра не должно делать программу полностью неработоспособной.

### 5.5. Репозиторий

- Общая логика, Windows-адаптер и будущий Linux-адаптер размещаются в одном Git-репозитории.
- Разные версии общей логики для Windows и Ubuntu не создаются.
- Документация проекта размещается в каталоге `docs/`.
- Служебные файлы AI Factory не являются заменой проектной документации.

## 6. Организация разработки

### 6.1. Основная среда

Основная разработка ведётся на Ubuntu с использованием OpenAI и AI Factory.

На Ubuntu разрабатываются:

- общее ядро;
- аудиообработка;
- VAD и сегментация;
- ASR-адаптеры;
- словарь;
- нормализация;
- автоматические тесты;
- сравнительные испытания моделей.

### 6.2. Этапы

#### Этап 1. Общее ядро на Ubuntu

Результат — консольный или минимальный прототип полного цикла:

```text
запись → сегментация → распознавание → готовый текст
```

#### Этап 2. Ранний Windows-прототип

Результат — минимальный вертикальный сценарий:

```text
горячая клавиша → запись → локальное ASR → буфер → вставка
```

Прототип создаётся до завершения полноценного интерфейса.

#### Этап 3. Windows MVP

Добавляются интерфейс, трей, настройки, словарь, безопасная вставка, модельные пакеты, диагностика и установщик.

#### Этап 4. Ubuntu-версия

После Windows MVP создаётся `LinuxAdapter` и пакет Ubuntu на базе общего ядра.

### 6.3. Сборка и тестирование

- Финальная Windows-сборка создаётся в Windows-среде или Windows CI.
- Финальный Windows-установщик проверяется на реальной Windows.
- Кросс-компиляция на Ubuntu не является единственным выпускным процессом.
- Общие автоматические тесты запускаются на Ubuntu и Windows.
- CI не заменяет ручную проверку микрофона, горячих клавиш, окна и вставки.

## 7. Установка и поставка

- Поставка осуществляется установщиком Windows либо комплектом установщика и локальных модельных пакетов.
- Пользователь не работает с командной строкой.
- Установщик автоматически размещает программу и обязательные зависимости.
- Установка возможна без интернета.
- Модельные пакеты устанавливаются локально.

- После удаления не сохраняются аудиозаписи.
- Пользователь может выбрать удаление настроек и словаря.

  - руководство пользователя;

  - перечень компонентов;
  - лицензии;

## 8. Проверка и приёмка

### 8.1. Набор испытаний

Набор включает:

- короткие русские резолюции;
- длинную диктовку не менее 10 минут;
- русскую речь с английскими терминами;
- фамилии;
- аббревиатуры;
- названия программ;
- даты;
- номера документов;
- суммы;
- перечисления;
- голосовые команды;
- паузы;
- умеренный офисный шум.

Используются реальные обезличенные фразы, характерные для предполагаемой эксплуатации.

### 8.2. Сравнение ASR

Проверяются:

1. GigaAM-v3-e2e CTC;
2. GigaAM-v3-e2e RNN-T;
3. GigaAM Multilingual 220M;
4. Whisper small INT8 через faster-whisper;
5. T-one — при наличии готового адаптера.

Для каждого варианта фиксируются:

- WER;
- CER;
- точность английских терминов;
- доля терминов, сохранённых латиницей;
- качество фамилий и аббревиатур;
- пунктуация;
- нормализация;
- время загрузки;
- RTF;
- задержка;
- CPU;
- ОЗУ;
- устойчивость длинной диктовки.

### 8.3. Критерии приёмки

| Проверка | Критерий |
|---|---|
| Запуск записи | Глобальная клавиша работает при свёрнутом окне; состояние меняется не позднее 1 секунды |
| Первый фрагмент | Первое слово контрольной фразы не теряется |
| Визуализация | Волна реагирует на микрофон; окно не перехватывает фокус |
| Русский режим | Контрольные русские резолюции распознаются локально и формируют редактируемый текст |
| Смешанный режим | С английским контрольным словарём не менее 90 % терминов тестового набора воспроизводятся в согласованном написании |
| Голосовые команды | При включённом режиме выполняется не менее 95 % команд контрольного набора |
| Команды отключены | Фразы команд остаются обычными словами |
| Длинная запись | Не менее 10 минут без программного лимита, потери порядка, пропусков и повторов на стыках |
| Целевое окно | При смене фокуса текст не вставляется в постороннее окно |
| Буфер обмена | Типовое текстовое и нетекстовое содержимое восстанавливается либо не перезаписывается небезопасным способом |
| Ошибка вставки | Текст остаётся доступен в буфере и как последний результат |
| Защищённое поле | Автоматическая вставка не выполняется |
| Автономность | Основной сценарий работает при заблокированном исходящем сетевом доступе |
| Конфиденциальность | Аудио и текст отсутствуют в журнале и постоянной истории |
| Установка | Установка без интернета и без установленной среды разработки |
| Целевой ПК | Интерфейс остаётся отзывчивым, показатели CPU, ОЗУ и задержки зафиксированы в протоколе |

### 8.4. Матрица приложений

Вставка проверяется как минимум в:

- Блокноте;
- Microsoft Word;
- обычном поле браузера;
- многострочном поле браузера;
- 1С;
- приложении с нестандартной обработкой `Ctrl+V`;
- поле пароля.

Известные ограничения фиксируются в руководстве и протоколе приёмки.

## 11. Контрольные решения после прототипа

До фиксации состава релизной сборки необходимо:

1. выбрать GigaAM-v3-e2e CTC или RNN-T для режима «Русский»;
2. выбрать GigaAM Multilingual 220M или Whisper small INT8 для режима «Русский + English»;
3. определить целесообразность включения T-one;

6. утвердить точный состав модельных пакетов;
7. зафиксировать известные ограничения вставки в поддерживаемых приложениях.

Эти решения уточняют реализацию и числовые нормативы, но не меняют согласованный пользовательский сценарий и обязательную автономность продукта.
