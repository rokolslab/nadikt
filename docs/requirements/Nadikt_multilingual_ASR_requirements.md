# «Надикт» (Nadikt)

## Требования к смешанной русско-английской речи и сменным ASR-движкам

**Дата:** 26 июля 2026 г.  
**Статус:** согласовано для включения в следующую редакцию ТЗ  
**Целевые ОС MVP:** Windows 10 и Windows 11 x64  
**Перспективная ОС:** Ubuntu  
**Режим работы:** полностью локальный, без передачи аудио и текста во внешние сервисы

## 1. Назначение документа

Документ устанавливает дополнительные требования к программе «Надикт» в части:

- распознавания русской речи с английскими терминами;
- поддержки нескольких локальных движков распознавания речи;
- выбора и переключения моделей;
- автономной поставки модельных пакетов;
- проверки качества и производительности моделей на целевом оборудовании.

Требования подлежат включению в следующую редакцию основного технического задания.

Policy поставки и trust model для model packages зафиксированы отдельно в
[`model_package_delivery_policy.md`](model_package_delivery_policy.md). Этот
документ уточняет delivery channels, trust anchor и runtime validation без
изменения согласованной редакции основного ТЗ.

## 2. Языковой сценарий MVP

### 2.1. Основной язык

Основным языком распознавания в MVP является русский.

### 2.2. Английские включения

Программа должна распознавать русскую речь, содержащую:

- отдельные английские слова;
- наименования программ и информационных систем;
- названия компаний и продуктов;
- технические термины;
- аббревиатуры;
- буквенно-цифровые обозначения.

Если английское слово или обозначение принято писать латиницей, программа должна по возможности сохранять его написание латиницей.

Примеры контрольных фраз:

- «обновить Windows и Microsoft Office»;
- «направить файл Excel по электронной почте»;
- «проверить сервер PostgreSQL и резервную копию database»;
- «согласовать pull request в GitHub»;
- «установить Docker Desktop в Windows»;
- «проверить подключение по SSH к Ubuntu Server»;
- «обновить конфигурацию 1С и выполнить backup базы данных».

### 2.3. Границы MVP

В MVP не требуется:

- полноценная диктовка документов на произвольных иностранных языках;
- перевод речи с одного языка на другой;
- автоматическое переключение языка внутри одной фразы;
- одновременное распознавание одной записи несколькими моделями;
- облачное распознавание в качестве основного или резервного режима.

## 3. Режимы распознавания

В настройках программы предусматриваются следующие режимы:

### 3.1. «Русский»

Режим предназначен для преимущественно русской речи. Предпочтительным исходным кандидатом является **GigaAM-v3-e2e**.

### 3.2. «Русский + English»

Режим предназначен для русской речи с английскими словами, названиями и техническими терминами.

Конкретная модель для этого режима определяется по результатам сравнительного тестирования:

- GigaAM Multilingual 220M;
- Whisper small INT8 через faster-whisper;
- иной локальный движок, если он покажет лучшие результаты и соответствует требованиям автономности и лицензирования.

### 3.3. Перспективный облегчённый режим

Модель **T-one** рассматривается как кандидат на быстрый потоковый режим распознавания русской речи.

Поддержка T-one не считается обязательной функцией MVP до завершения испытаний на целевом оборудовании.

## 4. Термины

В рамках проекта используются следующие определения:

- **ASR-движок** — программный компонент, выполняющий запуск модели и преобразование аудио в текст;
- **ASR-модель** — набор обученных весов и связанных с ними файлов, используемых движком;
- **модельный пакет** — подготовленный для автономной установки комплект модели, конфигурации, лицензии, контрольной суммы и метаданных;
- **faster-whisper** — ASR-движок на основе CTranslate2 для запуска совместимых моделей Whisper; faster-whisper не является самостоятельной моделью;
- **смешанная речь** — русская речь, содержащая отдельные английские слова, термины или обозначения.

## 5. Архитектурные требования

### M01. Единый интерфейс ASR-движка

Программа должна использовать единый внутренний интерфейс подключения движков, включающий как минимум:

- загрузку модели;
- проверку готовности;
- прогрев модели;
- распознавание аудиосегмента;
- завершение текущего распознавания;
- освобождение ресурсов;
- получение сведений о версии, языке и возможностях движка.

### M02. Разделение компонентов

Отдельными компонентами должны быть реализованы:

- захват звука;
- предварительный аудиобуфер;
- VAD и сегментация;
- ASR-движок;
- сборка текста из сегментов;
- пунктуация и нормализация;
- пользовательский словарь и замены;
- помещение текста в буфер обмена;
- вставка текста в активное приложение;
- пользовательский интерфейс и настройки.

Замена ASR-движка не должна требовать переработки остальных компонентов.

### M03. Ограничение одновременно загруженных моделей

На целевом ПК в каждый момент времени должна быть загружена только одна основная модель распознавания.

Параллельный запуск двух тяжёлых моделей в MVP не допускается.

### M04. Ручной выбор режима

Пользователь должен иметь возможность выбрать в настройках:

- «Русский»;
- «Русский + English».

Выбранный режим сохраняется после перезапуска программы.

### M05. Запрет автоматической смены модели внутри записи

Во время одного сеанса диктовки программа не должна автоматически выгружать и заменять ASR-модель.

Переключение модели допускается только вне активного сеанса записи.

### M06. Автономные модельные пакеты

Каждая поддерживаемая модель должна поставляться как локальный версионируемый пакет, содержащий:

- файлы модели;
- конфигурацию;
- точное наименование модели;
- версию или идентификатор ревизии;
- сведения о разработчике;
- текст лицензии;
- перечень используемых сторонних компонентов;
- контрольную сумму;
- сведения о совместимых версиях программы «Надикт».

Один и тот же package format должен поддерживать embedded installer, separate offline pack, removable media и явно запрошенный online-installer fallback. Runtime не различает канал доставки и принимает только локальный package path после validation gates.

### M07. Работа без интернета

Установка модельного пакета, переключение моделей и распознавание речи не должны требовать подключения к интернету.

Программа не должна автоматически загружать отсутствующую модель без явно запрошенного пользователем действия.

Online acquisition допускается только как installer-time fallback и не заменяет обязательный offline package channel. Hub IDs, repository names и URLs запрещены как runtime input вместо local path.

При отсутствии или повреждении модельного пакета программа должна:

- не начинать запись с неработоспособным движком;
- показать понятное сообщение;
- указать отсутствующий или повреждённый компонент;
- предложить выбрать установленную исправную модель.

### M08. Общий пользовательский словарь

Пользовательский словарь и правила замен должны применяться независимо от выбранного ASR-движка.

Словарь должен поддерживать как минимум:

- русские слова;
- английские слова;
- пары ошибочного и правильного написания;
- аббревиатуры;
- названия продуктов;
- буквенно-цифровые обозначения.

Для coding-dictation сценариев словарь и normalizer являются отдельным
engine-independent post-ASR компонентом. GigaAM может использоваться как working
candidate в private diagnostic runs, но правила замен не должны жить внутри
GigaAM/faster-whisper adapters и не выбирают final ASR model без publishable
benchmark evidence. Raw ASR metrics и normalized dictionary diagnostics
публикуются как отдельные views.

### M09. Безопасное переключение движка

При смене режима программа должна:

1. убедиться в отсутствии активной записи;
2. завершить работу текущего движка;
3. освободить занимаемые им ресурсы;
4. загрузить выбранную модель;
5. выполнить проверку и прогрев;
6. сообщить пользователю о готовности.

Если новая модель не загрузилась, программа должна сохранить возможность вернуться к последней работоспособной модели.

### M10. Расширяемость

Добавление нового ASR-движка не должно требовать изменения:

- механизма горячих клавиш;
- захвата звука;
- VAD и сегментации;
- плавающего окна;
- трея;
- пользовательского словаря;
- механизма вставки;
- логики безопасного восстановления результата.

## 6. Требования к ресурсам

Требования должны проверяться на эталонном ПК:

- Intel Core i3 10-го поколения;
- 16 ГБ оперативной памяти;
- без дискретной видеокарты;
- Windows 10 или Windows 11 x64;
- системный SSD.

На эталонном ПК:

- программа не должна одновременно держать в памяти несколько тяжёлых ASR-моделей;
- фоновая работа не должна заметно мешать офисным приложениям;
- отсутствие дискретной видеокарты не должно блокировать основной сценарий;
- каждая включённая в поставку модель должна пройти отдельное измерение загрузки ЦП, потребления ОЗУ и задержки;
- точные предельные показатели фиксируются в ТЗ после сравнительного прототипа.

## 7. Сравнительный прототип

### 7.1. Проверяемые варианты

До окончательного выбора моделей необходимо испытать:

1. GigaAM-v3-e2e;
2. GigaAM Multilingual 220M;
3. Whisper small INT8 через faster-whisper;
4. T-one — при наличии рабочего интеграционного прототипа.

Whisper medium, large и другие более тяжёлые варианты допускаются к испытаниям, но не включаются в MVP без подтверждения приемлемой производительности на эталонном ПК.

### 7.2. Тестовый набор

Тестовый набор должен включать:

- чистую русскую речь;
- русские резолюции с английскими терминами;
- названия программ и информационных систем;
- фамилии и имена;
- аббревиатуры;
- номера документов и заказов;
- даты и сроки;
- суммы и единицы измерения;
- перечисления;
- короткие фразы;
- длинную непрерывную диктовку продолжительностью не менее 10 минут;
- речь с паузами и фоновым офисным шумом.

В тестовый набор должны входить реальные или обезличенные фразы, характерные для предполагаемого применения программы.

### 7.3. Измеряемые показатели

Для каждого варианта фиксируются:

- WER русского текста;
- CER русского текста;
- точность английских терминов;
- доля терминов, сохранённых латиницей;
- качество фамилий, аббревиатур и наименований;
- качество пунктуации;
- качество нормализации чисел и дат;
- время холодной загрузки;
- время первого распознавания после запуска;
- RTF;
- задержка между остановкой записи и готовностью текста;
- максимальное потребление ОЗУ;
- средняя и максимальная загрузка процессора;
- устойчивость на длинной диктовке;
- отсутствие пропусков и повторов на границах аудиосегментов.

### 7.4. Правило выбора

В основное ТЗ включаются только модели, которые:

- работают полностью локально;
- допускают законное распространение в составе выбранной схемы поставки;
- стабильно работают на эталонном ПК;
- обеспечивают приемлемое качество на целевом наборе фраз;
- не требуют дискретной видеокарты;
- не приводят к неприемлемому замедлению офисных приложений.

Модель для режима «Русский + English» определяется по итогам теста, а не только по опубликованным характеристикам.

## 8. Предварительный состав MVP

Предлагается зафиксировать:

1. **режим «Русский»** — GigaAM-v3-e2e либо более подходящая модель GigaAM, подтверждённая испытаниями;
2. **режим «Русский + English»** — победитель сравнения GigaAM Multilingual 220M и Whisper small INT8 через faster-whisper;
3. единый интерфейс ASR-движков;
4. локальные модельные пакеты;
5. ручное переключение режимов;
6. загрузку только одной модели;
7. общий пользовательский словарь;
8. отсутствие автоматического облачного резервирования;
9. возможность последующего подключения T-one и иных локальных моделей.

## 9. Критерии приёмки

Требования считаются выполненными, если:

1. пользователь может выбрать один из предусмотренных режимов;
2. выбранный режим сохраняется после перезапуска;
3. программа распознаёт русский текст с английскими контрольными терминами;
4. английские термины из согласованного тестового набора сохраняются латиницей с установленной по итогам прототипа точностью;
5. при смене режима предыдущая модель освобождает ресурсы;
6. во время записи смена модели заблокирована;
7. все модельные пакеты устанавливаются и работают без интернета;
8. повреждение или отсутствие пакета обрабатывается без аварийного завершения программы;
9. пользовательский словарь действует во всех поддерживаемых режимах;
10. новый движок может быть добавлен без изменения механизма записи и вставки;
11. каждая поставляемая модель проходит испытание на эталонном ПК;
12. аудио и распознанный текст не передаются во внешние сервисы.
